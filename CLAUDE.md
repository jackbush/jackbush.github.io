## Architecture

Personal site built with Astro 6 (no JS framework). A printable CV (below), and a home page (`src/pages/index.astro`) with a short intro and a projects/roles toggle:

- **Projects** (default) lists side projects, on the light page (the theme colour).
- **Roles** shows past roles, on the dark page (its inverse).
- The toggle is an accessible tablist; switching updates the `?mode=` URL param (`projects`|`roles`) via `history.replaceState`, so either mode is directly shareable. It also swaps the page `<title>` (`Jack Bush | Projects` / `| Roles`) and the favicon (white circle / black circle). An inline script applies the correct theme before first paint on `?mode=roles` loads. First paint is just the heading and intro: the toggle and lists (`.tabs`) stay hidden (`html.tabs-pending`) until the page script has set them up, then fade in, so `?mode=roles` never flashes the project cards.
- The active tab is filled with the page's text colour, its label in the page colour; the inactive tab is the page with a text-colour label; the frame is the text colour. Nothing uses the other page's colours. Styles key off `data-theme`, so the pre-paint script gets it right.
- **The switch:** clicking a tab (or the arrow keys, from the tab's centre) spreads the new page colour out from the click on a canvas, with a wobbling outline; the intro stays and changes colour as it passes, the old list fades, and the new list appears inside the spreading shape. The browser's own bars take one flat colour (`theme-color`, and Safari's tint from `html`'s background), so they follow the page along the top edge (`topEdge` in `backdrop.ts`), changing `barsLead` (in `theme.ts`) before a switch covers it; `viewport-fit=cover` lets the canvas itself reach under Safari's bars where it allows. With `prefers-reduced-motion`, or without WebGL2, the switch is instant/plain CSS.

**Content** lives in `src/data/projects.ts` and `src/data/roles.ts` — edit those to update the lists. A `Role`'s dates are its first and last month (`start`, `end` as `"YYYY-MM"`); an optional `cvOrganisation` replaces its organisation on the CV; it supports an optional `listItems: string[]` rendered as a bullet list, and optional `caseStudies` (`label`, optional `url`): underlined text lines led by an article icon, fading slightly on hover or while tapped. One without a `url` opens a password dialog (`CaseStudyDialog.astro`, outside `.page` so the ink copies don't draw it); it's a placeholder, so no password works. A project's `cover` sets its card: `landscape` (3:2 header, optionally a looping `video` over the image as poster), `phone` (screenshot, a third of the width) or `square` (1:1, a third of the width). Covers always keep their ratio; side covers alternate left and right, and stack above the text when the card is narrower than 32rem (a container query). Every card but a phone one is a 1px box in the text colour with a line between cover and text; its corners and the toggle's share `--radius` in `global.css`. A project with `vimeo` instead of `url` embeds the video and isn't a link. Any project can add a `link` (`label`, `url`): a bar along the bottom of the card with a chevron. Links to my other sites on `jackbush.github.io` open in the same tab with `?from=home`, which their back buttons (glimmers, albums) read to point here; other links open in a new tab. Cover files are in `src/assets/covers/` (the glimmers' are copied from their sketch folders); the build warns about a project without one. No CMS or content collections.

**CV** (`src/pages/pdf.astro`, at `/pdf`): the intro's lead line, the skills in `src/data/cv.ts`, roles (without case studies) and `src/data/education.ts` as A4 sheets on cream paper with navy/slate/grey text, standalone from `Layout.astro` and the themes. A script deals the blocks onto sheets (a section heading stays with the item after it) and shrinks them to fit the preview. The sheets are plain boxes in one `<main>`, so the PDF's tags read as one document; nothing on a sheet is positioned, since Chrome paints positioned boxes last and the PDF's text order (what ATSs read) would follow. A contact whose label is only part of its address (LinkedIn) sets `full`, written as transparent full-size text on a line of no height under the contact line, so it's in the PDF's text without moving anything. `src/data/cv.ts` lists one version per location (`?location=nz|uk`; the page previews the first) and every design setting (`cvDesign`: colours, sizes, weights, spacing, margins), written as CSS vars. A sidebar edits them live, keeping edits in the URL; below 1024px the page hides the sheets and sidebar for a short message and the download button. `src/integrations/cv-pdfs.ts` prints every version with headless Chrome (`CHROME_PATH`, else the usual install paths; it fails without one), using the page's print styles: after each build, from `dist/` into `dist/cv/` with the saved settings, and under `npm run dev` whenever a PDF is requested, with the sidebar's edits (the download passes them in the PDF's query). "Download PDFs", at the bottom of the sidebar, downloads them all. The on-screen preview paginates in the viewer's own browser, so outside Chrome its page breaks can differ slightly from the PDFs'.

**Theme and switch settings** all live in `src/data/theme.ts`: the theme colours (each the Projects page; the Roles page is its inverse, so each page is the other's text; the first, putty, is the default, and the left and right arrow keys (outside the toggle and text fields) or a sideways swipe cycle through them at once; nothing remembers the choice), text opacities, and the switch's motion and outline (tuned live in the `homepage` sketch in the glimmers repo, whose pane uses the same names). Text colours are never picked: each page's text is its inverse, at full strength for headings, strong text and lines, and at a lower opacity for body text. `theme.ts` fails the build if main or minor text drops below 5.7:1 in any theme.

**Theming:** `Layout.astro` sets `data-theme` (`projects|roles`) on `<html>` and writes the default theme's colours from `theme.ts` as CSS vars (`--projects-bg`, `--projects-main|minor`, the same for roles, the cards' wash, and the backdrop's `--ink-*` greys), which the page script rewrites, with the backdrop's page colours, on a theme change; `global.css` maps them to the semantic `--color-*` vars, with a `--transition-duration` (300ms) fade between themes for the plain-CSS fallback. The page colour is on `html`, not `body`, so the canvas can sit between them.

**Backdrop** (`src/scripts/backdrop.ts`, wired up in `index.astro`'s script, styles at the end of `global.css`): a WebGL2 canvas behind the page draws the page colour and each switch, only when something changes. Once it has drawn, `html.backdrop-on` is set and the page is drawn four times in one grid cell (`.page`): the real `<main>`, with its text transparent but still there for focus, selection, links and screen readers, and three `aria-hidden`, `inert` copies (`.ink`) that only draw text (they drop images, videos and iframes; cover boxes keep their size without them), in blend layers (multiply, difference, plus-lighter) whose greys turn whatever page colour is under each glyph into that page's text colour. That's why text flips pixel by pixel as a switch passes. The page itself is never a stacking context between the copies and the canvas, or the blends stop reaching it. The new list's reveal is an SVG polygon clip set each frame from the switch's outline (`radiusAt`), so it matches the canvas edge; link and button hover is mirrored onto the copies.

**Type styles:** the complete type set lives as one commented block in `global.css` (`h1`/`h2`/`h3` and `.text-strong`/`.text-body`/`.text-meta`) — edit a style there and it changes everywhere; components carry layout margins only.

**Components:** `Layout.astro` (head, the backdrop canvas, skip link, 740px container), `ProjectItem.astro` (the project card, in its cover's layout), `Roles.astro` (each role: organisation, role, dates, description, optional bullet list and case studies), `CaseStudyDialog.astro` (the password dialog), `Chevron.astro` (the chevron on project link bars).

**Deployment:** Push to `source` branch triggers GitHub Actions build → GitHub Pages deploy automatically.

## Key Constraints

- **Accessibility is non-negotiable:** Skip link, ARIA tab semantics on the toggle, 44×44px minimum touch targets, contrast ≥5.7:1, focus rings visible.
- **CSS units:** Use `rem` consistently — do not mix `rem` and `px` for the same sizing concern.
- **Viewport meta:** Always include `initial-scale=1` alongside `width=device-width`.
- **No framework:** Vanilla JS only for interactivity. Keep it minimal.
